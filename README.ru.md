# Табличные модели: ModernNCA и головы энкодера

[English version](README.md)

Исследовательское сравнение четырёх моделей на 30 табличных датасетах, включая `walking-activity`: 15 сидов на каждую пару «датасет — модель», всего 1 800 оценок на test. В репозитории находятся данные, код экспериментов и архив результатов.

## Модели

| Имя в CLI | Метод |
| --- | --- |
| `modernnca` | Нейросетевой энкодер с PLR-эмбеддингами числовых признаков и дифференцируемым предсказанием по соседям, взвешенным по расстоянию. |
| `catboost` | CatBoost на исходных признаках с собственной обработкой категорий. |
| `encoder_linear` | Энкодер и линейная голова обучаются совместно; cross-entropy для классификации, один выход для регрессии. |
| `encoder_catboost` | Энкодер обучается с функцией потерь ModernNCA, затем фиксируется; CatBoost обучается на его эмбеддингах. |

Гибрид всегда берёт параметры энкодера из `modernnca_best_params.json`. При подборе головы эмбеддинги вычисляются один раз; финальные прогоны обучают энкодер заново для каждого сида. Сохранённые гиперпараметры не являются весами обученной сети.

## Протокол

- 20 задач классификации и 10 задач регрессии. Точные названия датасетов — ключи `modernnca_best_params.json`. Пять групп пользователей покрывают 29 датасетов; `walking-activity` запускается отдельно.
- Для каждого сида создаётся разбиение train/validation/test 64%/16%/20%, стратифицированное для классификации. Предобработка нейросети обучается на train: заполнение числовых пропусков средним и стандартизация; отдельная категория пропусков и one-hot encoding категориальных входов.
- Optuna TPE использует validation accuracy (максимизация) или RMSE (минимизация), сид подбора 0, лимит 100 trials и остановку после 10 подряд без улучшения. Гибрид переиспользует параметры энкодера ModernNCA и отдельно подбирает голову CatBoost.
- Финальная оценка на test: сиды 0–14. Нейросети: до 200 эпох, patience 20, batch size 1 024. CatBoost: до 2 000 итераций, ранняя остановка с patience 50.
- Диапазоны `hidden_dim` и `embed_dim` ограничены 64–512. Это изменение и дополнительные головы делают проект адаптацией исследования, а не точным воспроизведением статьи. Статья включена в репозиторий: [KNN.pdf](KNN.pdf).

## Установка и запуск

Команды выполняются из корня репозитория на Linux. Серверные прогоны использовали Python 3.12, PyTorch 2.5.1 с CUDA 12.1 и NVIDIA RTX A4000 (16 ГБ). Версии остальных зависимостей в `requirements.txt` закреплены не полностью.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
python -m pip install -r requirements.txt
tmux new -s benchmark
```

Пример запуска четырёх моделей на одном датасете и выделенной GPU:

```bash
python -u run_benchmark.py --user user3 --gpu 0 --datasets stock \
  --models modernnca catboost encoder_linear encoder_catboost \
  --results-dir runs/stock 2>&1 | tee runs_stock.log
```

Без `--datasets` запускается группа, назначенная `--user user1`–`user5`; для отдельного датасета укажите `--datasets walking-activity`. `--gpu` — физический индекс согласованной GPU. Каждому пользователю нужна своя копия репозитория. По умолчанию выбраны только `modernnca catboost`.

Добавьте `--smoke` для минимальной проверки: один trial, один сид, одна эпоха, два дерева; датасет по умолчанию — `stock`. Для CPU замените `--gpu 0` на `--device cpu`. Остальные параметры: `python run_benchmark.py --help`. Отключение от tmux: Ctrl+B, затем D; возвращение: `tmux attach -t benchmark`.

Для новых экспериментов задавайте отдельный `--results-dir runs/<имя>`, чтобы сохранить архив в репозитории. Создаются CSV метрик и времени, JSON прогресса и `optuna.db`. Консольный лог показывает датасет, модель, этап, прошедшее время и уточняемый прогноз окончания; `tee` сохраняет его в файл. Повтор команды с тем же каталогом продолжает совместимые исследования Optuna, но финальные прогоны по сидам выполняются заново.

## Архив результатов

| Файл в `results/` | Содержимое |
| --- | --- |
| `benchmark_all_30_datasets_4_models_1800_results.csv` | Итоговые метрики, сиды, конфигурации, источники и доступные измерения времени. |
| `benchmark_all_30_datasets_4_models_full.log` | Объединённые исходные логи и записи измерений времени. |
| `optuna.db` | Объединённая история подбора: 120 исследований, 30 датасетов, четыре модели, 2 707 trials. |

Итоговый CSV — источник метрик. База сохраняет доступные архивные исследования; старые логи могут содержать другие запуски того же исследования. Подробные времена обучения и инференса есть для `walking-activity` и двух моделей с альтернативными головами. Для остальных ранних запусков есть только логи Optuna; пустые поля времени означают отсутствие измерений. Инференс измерен на тестовом батче, а не на одном запросе.

Сравнивайте среднее по сидам внутри каждого датасета: accuracy выше — лучше, RMSE ниже — лучше. Нельзя усреднять исходные accuracy и RMSE между задачами. Выбор подвыборки, изменение разбиения между сидами, незакреплённые версии зависимостей и общая нагрузка сервера ограничивают обобщение выводов и точное воспроизведение времени.

## Код и проверки

`Stream1_DataExtraction.py` — загрузка и разбиения; `Stream2_Preprocessing.py` — признаки; `Stream3_ModernNCA.py` — энкодер; `Stream4_Train.py` — обучение с соседями; `Stream5_NeuralHeads.py` — дополнительные головы; `steram5.py` — базовые модели и подбор. `run_benchmark.py` — запуск из CLI, `run_progress.py` — прогресс и время, `Pipeline.ipynb` — интерактивный запуск.
